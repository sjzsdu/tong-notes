# Flow360 核心流水线流程

## 整体流程架构

```mermaid
flowchart TD
    A[用户输入] --> B{输入类型判断}
    B -->|几何体| C[geometryConversionPipeline]
    B -->|表面网格| D[inhouseSurfaceMesherPipeline]
    B -->|体积网格| E[inhouseVolumeMesherPipeline]
    B -->|案例配置| F[casePipeline]
    
    C --> G[几何体转换和验证]
    D --> H[表面网格生成]
    E --> I[体积网格生成]
    
    G --> J[网格元数据处理]
    H --> J
    I --> J
    
    J --> K[meshMetaDataPipeline]
    K --> L[meshVisualizePipeline]
    
    F --> M[案例验证和预处理]
    M --> N[Flow360求解器执行]
    N --> O[结果后处理]
    
    L --> P[可视化文件生成]
    O --> Q[caseVisualizePipeline]
    Q --> R[报告生成]
    
    P --> S[最终输出]
    R --> S
```

该流程图展示了Flow360从输入到输出的完整处理链路。系统支持多种输入格式（几何体、网格、案例配置），通过不同的pipeline进行处理，最终生成可视化结果和分析报告。

## 核心Pipeline时序图

```mermaid
sequenceDiagram
    participant User as 用户
    participant Client as PipelineScript
    participant Validator as 验证模块
    participant Solver as Flow360Solver
    participant Processor as 后处理器
    participant Visualizer as 可视化器
    
    User->>Client: 提交案例配置
    Client->>Validator: validateFlow360Case
    Validator->>Client: 验证结果
    
    alt 验证成功
        Client->>Client: downloadAndUncompressFiles
        Client->>Client: runMeshPartitioner
        Client->>Client: runMeshProcessor
        Client->>Solver: runFlow360Solver
        Solver->>Client: 求解结果
        
        Client->>Processor: 生成CSV监控文件
        Client->>Processor: calculateWorkUnit
        Processor->>Client: 工作量统计
        
        Client->>Visualizer: caseVisualizePipeline
        Visualizer->>Client: GLTF可视化文件
        
        Client->>User: 上传最终结果
    else 验证失败
        Validator->>User: 返回错误信息
    end
```

该时序图详细展示了案例处理的关键步骤和模块间的交互关系。验证阶段确保输入数据的正确性，求解阶段执行核心计算，后处理和可视化阶段生成用户所需的输出结果。

## Pipeline错误处理机制

```mermaid
stateDiagram-v2
    [*] --> Running
    Running --> Success : 正常完成
    Running --> Error : 执行异常
    
    Error --> Retry : retry < maxRetries
    Error --> Failed : retry >= maxRetries
    
    Retry --> Running
    Success --> [*]
    Failed --> ErrorHandling
    
    ErrorHandling --> LogError : 记录错误日志
    ErrorHandling --> GatherError : 收集分布式错误
    ErrorHandling --> UserNotify : 用户错误通知
    
    LogError --> [*]
    GatherError --> [*]
    UserNotify --> [*]
```

错误处理机制采用多层次策略：运行时监控、自动重试、分布式错误收集和用户友好的错误反馈。这确保了系统的稳定性和用户体验。

## 关键组件交互

各Pipeline通过PipelineScript基类实现统一的执行模式，包括：

1. **资源管理**：自动下载输入文件，上传输出结果
2. **命令执行**：支持本地和分布式执行模式
3. **进度监控**：实时跟踪执行状态和性能指标
4. **错误恢复**：智能重试机制和错误诊断
5. **缓存优化**：网格数据缓存和增量处理

每个Pipeline都遵循"下载-处理-上传"的标准模式，确保了系统的一致性和可维护性。
