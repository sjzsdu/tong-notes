# RD-Agent 核心架构设计

## 总体架构设计

RD-Agent采用分层架构设计，从底层抽象到上层应用逐层构建，确保系统的可扩展性和维护性。

```mermaid
graph TB
    subgraph "核心抽象层 (Core Layer)"
        EvolvingFramework[演化框架]
        Scenario[场景抽象]
        Agent[智能体基类]
        Evaluation[评估系统]
        KnowledgeBase[知识库]
    end
    
    subgraph "演化机制"
        EvoStep[演化步骤]
        EvoStrategy[演化策略]
        RAGStrategy[RAG策略]
        QueriedKnowledge[查询知识]
    end
    
    subgraph "实验管理"
        Experiment[实验管理]
        Task[任务抽象]
        Developer[开发者接口]
        Proposal[提议生成]
    end
    
    EvolvingFramework --> EvoStep
    EvolvingFramework --> EvoStrategy
    EvoStrategy --> RAGStrategy
    RAGStrategy --> QueriedKnowledge
    
    Agent --> EvolvingFramework
    Agent --> Evaluation
    Scenario --> Developer
    Developer --> Experiment
    Experiment --> Task
    KnowledgeBase --> QueriedKnowledge
```

**核心架构特点：**
- **演化驱动**: 基于演化算法的持续改进机制
- **知识增强**: RAG(检索增强生成)模式集成领域知识
- **场景抽象**: 支持多种应用场景的统一抽象
- **反馈循环**: 完整的评估反馈机制

## 核心类设计

### 1. 演化框架类图

```mermaid

        +query_knowledge()*

        +clone() EvolvableSubjects

    class EvoStep~T~ {
        +evolvable_subjects: T
        +queried_knowledge: QueriedKnowledge
        +feedback: Feedback
    }
    
    class EvolvingStrategy~T~ {
        <<abstract>>
        +scen: Scenario
        +evolve(subjects, trace, knowledge)*
    }
    
    class RAGStrategy~T~ {
        <<abstract>>
        +knowledgebase: EvolvingKnowledgeBase
        +query(evo, trace)**
        +load_or_init_knowledge_base()**
    }
    
    class EvolvingKnowledgeBase {
        <<abstract>>
        +query() QueriedKnowledge*
    }
    
    EvolvingFramework --> EvolvableSubjects
    EvolvingFramework --> EvoStep
    EvolvingStrategy --> EvoStep
    RAGStrategy --> EvolvingKnowledgeBase
    EvoStep *-- EvolvableSubjects
```

**演化框架设计特点：**
- **泛型设计**: 使用TypeVar支持不同类型的演化主体
- **步骤记录**: EvoStep记录每次演化的完整信息
- **知识集成**: RAGStrategy提供知识检索能力
- **策略模式**: 不同场景可使用不同的演化策略

## 设计模式应用

```mermaid

        <<interface>>
        +execute()*
    }
    
    class ConcreteStrategyA {
        +execute()
    }
    
    class ConcreteStrategyB {
        +execute()
    }
    
    Context --> Strategy
    Strategy <|-- ConcreteStrategyA
    Strategy <|-- ConcreteStrategyB
    
    note for Context "在RD-Agent中对应\nEvolvingStrategy"
    note for ConcreteStrategyA "对应具体场景策略\n如QuantStrategy"
```

**策略模式在RD-Agent中的应用：**
- **演化策略**: 不同场景使用不同的演化算法
- **评估策略**: 不同任务使用不同的评估方法
- **代码生成策略**: 支持多种代码生成方式

## 核心工作流程

### 演化循环状态机

```mermaid
stateDiagram-v2
    [*] --> 初始化: 创建初始实验
    
    初始化 --> 知识检索: 启动RAG查询
    知识检索 --> 演化策略: 获取相关知识
    演化策略 --> 代码开发: 生成改进方案
    代码开发 --> 执行验证: 实现并测试
    执行验证 --> 评估反馈: 获取执行结果
    
    评估反馈 --> 检查循环: 是否达到最大循环数?
    检查循环 --> 知识检索: 否,继续下一轮
    检查循环 --> 结果输出: 是,结束循环
    
    执行验证 --> 错误处理: 执行失败
    错误处理 --> 知识检索: 记录错误,重新尝试
    
    结果输出 --> [*]: 完成
```

**工作流程特点：**
- **迭代优化**: 通过多轮循环持续改进
- **知识驱动**: 每轮都会检索相关知识
- **错误恢复**: 具备错误处理和恢复机制
- **反馈学习**: 基于反馈调整后续策略

## 扩展性设计

RD-Agent的核心架构设计充分考虑了扩展性：

1. **插件化架构**: 新场景只需实现核心接口即可集成
2. **策略可替换**: 演化策略、评估策略等都可独立替换
3. **知识库可扩展**: 支持多种知识源的集成
4. **组件松耦合**: 各组件通过接口交互，降低依赖

这种设计使得RD-Agent能够轻松适应新的研究领域和应用场景，同时保持系统的稳定性和可维护性。
