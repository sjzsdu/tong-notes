# RD-Agent 系统工作流程与状态管理

## 系统工作流程总览

RD-Agent的核心工作流程基于"研究-开发"循环（R&D Loop），通过假设生成、实验设计、代码实现、执行评估等步骤形成完整的自动化研发闭环。

```mermaid
graph TD
    subgraph "RD-Agent工作流程"
        A[任务输入] --> B[场景初始化]
        B --> C[假设生成 Hypothesis]
        C --> D[实验设计 Experiment]
        D --> E[代码开发 Coding]
        E --> F[代码执行 Running]
        F --> G[结果评估 Evaluation]
        G --> H[反馈总结 Feedback]
        
        H --> I{是否继续迭代?}
        I -->|是| J[更新知识库]
        J --> C
        I -->|否| K[输出最终结果]
        
        subgraph "并行处理"
            L[知识检索]
            M[错误处理]
            N[进度监控]
        end
        
        C -.-> L
        E -.-> M
        F -.-> N
    end
```

**工作流程特点：**
- **闭环设计**: 从假设到反馈形成完整闭环
- **迭代优化**: 支持多轮迭代持续改进
- **知识驱动**: 每个环节都有知识支持
- **错误恢复**: 具备完善的错误处理机制

## 核心状态机设计

### RD-Loop状态转换

```mermaid
stateDiagram-v2
    [*] --> 初始化: 启动系统
    
    state 初始化 {
        [*] --> 加载配置
        加载配置 --> 创建场景
        创建场景 --> 初始化组件
        初始化组件 --> [*]
    }
    
    初始化 --> 假设生成: 开始R&D循环
    
    state R&D循环 {
        假设生成 --> 实验设计: 生成研究假设
        实验设计 --> 代码开发: 设计实验方案
        代码开发 --> 代码执行: 实现代码逻辑
        代码执行 --> 结果评估: 执行代码获取结果
        结果评估 --> 反馈总结: 评估实验结果
        反馈总结 --> 循环判断: 生成改进反馈
        
        state 循环判断 <<choice>>
        循环判断 --> 假设生成: 继续迭代
        循环判断 --> 结果输出: 达到终止条件
    }
    
    R&D循环 --> 结果输出: 完成所有循环
    结果输出 --> [*]: 结束
    
    note right of R&D循环 : 核心循环逻辑\n支持最大循环次数限制
```

**状态机特点：**
- **状态清晰**: 每个状态都有明确的职责和输出
- **转换条件**: 基于评估结果和循环次数的智能转换
- **错误恢复**: 每个状态都支持错误处理和重试
- **可监控**: 状态转换过程完全可视化监控

### 详细工作流程时序图

```mermaid
sequenceDiagram
    participant U as 用户
    participant L as RD-Loop主控制器
    participant H as 假设生成器
    participant E as 实验设计器
    participant C as 代码开发器
    participant R as 代码执行器
    participant S as 结果评估器
    participant K as 知识库
    
    U->>L: 提交研究任务
    L->>L: 初始化场景和组件
    
    loop R&D循环 (最大循环次数)
        L->>H: 请求生成假设
        H->>K: 查询相关知识
        K-->>H: 返回知识内容
        H->>H: 生成研究假设
        H-->>L: 返回假设
        
        L->>E: 基于假设设计实验
        E->>E: 分解实验任务
        E-->>L: 返回实验方案
        
        L->>C: 开发实验代码
        C->>K: 查询代码模板
        K-->>C: 返回代码示例
        C->>C: 生成实现代码
        C-->>L: 返回代码实现
        
        L->>R: 执行实验代码
        R->>R: 运行代码获取结果
        R-->>L: 返回执行结果
        
        L->>S: 评估实验结果
        S->>S: 分析结果质量
        S-->>L: 返回评估反馈
        
        alt 需要继续迭代
            L->>K: 更新知识库
            K-->>L: 确认更新
            Note over L: 准备下一轮迭代
        else 达到终止条件
            L->>U: 返回最终结果
            break 结束循环
        end
    end
```

**时序特点：**
- **组件协调**: 多个组件有序协作完成复杂任务
- **知识集成**: 知识库贯穿整个执行过程
- **反馈学习**: 每轮结果都会更新知识库
- **智能终止**: 基于多种条件的智能终止机制

- **多维评估**: 从新颖性、可行性、价值等多维度评估
- **智能筛选**: 自动选择最有潜力的假设

### 3. 执行与评估流程

```mermaid
stateDiagram-v2
    [*] --> 环境准备: 初始化执行环境
    
    环境准备 --> 代码执行: Docker容器启动
```

**执行评估特点：**
- **容器化执行**: 基于Docker的隔离执行环境
- **错误恢复**: 自动错误检测和修复机制
- **多维评估**: 从准确性、效率等多个维度评估结果
- **反馈生成**: 自动生成针对性的改进建议
