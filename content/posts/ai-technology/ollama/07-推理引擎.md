# 推理引擎详解

## 🧠 推理引擎架构

Ollama的推理引擎基于**分离式设计**，将推理计算独立为子进程，通过HTTP通信实现解耦和容错。

```mermaid
graph TB
    subgraph "Ollama主进程"
        LLMServer[LLM服务器<br/>llmServer struct]
        HTTPClient[HTTP客户端<br/>推理请求代理]
        ProcessMgr[进程管理<br/>启动/监控/重启]
    end
    
    subgraph "Runner子进程"
        RunnerMain[运行器入口<br/>Execute函数]
        HTTPServer[HTTP服务器<br/>localhost:port]
        ModelLoader[模型加载器<br/>GGML/llama.cpp]
    end
    
    subgraph "后端适配层"
        GGML[GGML后端<br/>硬件抽象]
        LlamaCpp[llama.cpp<br/>推理内核]
        Backends[计算后端<br/>CUDA/ROCm/Metal]
    end
    
    LLMServer --> HTTPClient
    LLMServer --> ProcessMgr
    
    ProcessMgr --> RunnerMain
    HTTPClient --> HTTPServer
    
    RunnerMain --> HTTPServer
    HTTPServer --> ModelLoader
    
    ModelLoader --> GGML
    GGML --> LlamaCpp  
    LlamaCpp --> Backends
```

## 🚀 推理流程详解

### 端到端推理管道
```mermaid
sequenceDiagram
    participant Client as 客户端
    participant Server as Ollama服务器
    participant Runner as Runner进程
    participant Model as 模型后端
    participant GPU as GPU设备
    
    Client->>Server: 推理请求
    Server->>Server: 解析prompt和参数
    
    Server->>Runner: POST /completion
    Note over Runner: HTTP服务器接收请求
    
    Runner->>Runner: 验证请求格式
    Runner->>Model: 创建推理序列
    
    Model->>GPU: 分配KV缓存空间
    GPU-->>Model: 缓存就绪
    
    Model->>Model: 对输入进行tokenization
    
    loop 自回归生成
        Model->>GPU: Forward pass计算
        GPU->>GPU: 矩阵乘法运算
        GPU->>GPU: 注意力计算
        GPU->>GPU: Feed-forward计算
        GPU-->>Model: 返回logits
        
        Model->>Model: 应用采样策略
        Model->>Model: 选择下一个token
        
        alt 非结束token
            Model-->>Runner: 流式返回token
            Runner-->>Server: HTTP chunk响应
            Server-->>Client: 实时输出
        else 结束token或达到长度限制
            Model-->>Runner: 最终响应+统计信息
            Runner-->>Server: 完整响应
            Server-->>Client: 结束流
        end
    end
    
    Model->>GPU: 释放KV缓存
    GPU-->>Model: 缓存清理完成
```

### GPU内存分配策略
```mermaid
flowchart TD
    Start[开始内存分配] --> EstimateMemory[估算内存需求]
    
    EstimateMemory --> CalcModel[计算模型权重大小<br/>layers × hidden_size × dtype]
    EstimateMemory --> CalcKV[计算KV缓存大小<br/>batch_size × seq_len × num_heads]
    EstimateMemory --> CalcIntermediate[计算中间变量<br/>激活值 + 梯度缓存]
    
    CalcModel --> TotalMemory[总内存需求]
    CalcKV --> TotalMemory
    CalcIntermediate --> TotalMemory
    
    TotalMemory --> CheckAvailable{检查可用VRAM}
    
    CheckAvailable -->|充足| AllocateAll[分配完整内存]
    CheckAvailable -->|不足| PartialOffload[部分卸载到CPU]
    CheckAvailable -->|严重不足| Error[返回内存不足错误]
    
    AllocateAll --> OptimizeLayout[优化内存布局<br/>连续分配 + 对齐]
    PartialOffload --> SelectLayers[选择卸载层<br/>优先卸载大层]
    
    OptimizeLayout --> Success[分配成功]
    SelectLayers --> Success
    
    Success --> Monitor[监控内存使用<br/>OOM预防]
```

### 采样参数调优指南
| 参数 | 范围 | 效果 | 推荐场景 |
|------|------|------|----------|
| **temperature** | 0.1-2.0 | 控制创造性 | 0.7(对话), 0.1(代码) |
| **top_k** | 1-100 | 限制候选数量 | 40(平衡), 1(确定性) |
| **top_p** | 0.1-1.0 | 动态候选集 | 0.9(创意), 0.5(准确) |
| **repeat_penalty** | 0.9-1.3 | 避免重复 | 1.1(通用), 1.0(禁用) |

### 性能优化检查清单
- [ ] **模型量化**: 启用FP16或INT8量化减少内存占用
- [ ] **批量推理**: 合并多个请求提高GPU利用率  
- [ ] **KV缓存**: 启用注意力缓存避免重复计算
- [ ] **内存预分配**: 避免推理过程中的动态分配
- [ ] **异步处理**: 使用流式输出减少感知延迟
- [ ] **硬件选择**: 根据模型大小选择合适的GPU配置
