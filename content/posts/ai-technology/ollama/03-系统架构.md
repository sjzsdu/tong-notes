# 系统架构详解

## 🏗️ 整体架构

Ollama 采用**分层架构**设计，从上到下分为接口层、服务层、调度层、推理层和硬件层：

```mermaid
graph TB
    subgraph "接口层 - Interface Layer"
        CLI[CLI工具]
        WebAPI[Web API] 
        OpenAI[OpenAI兼容API]
    end
    
    subgraph "服务层 - Service Layer"  
        Router[路由器<br/>Gin Router]
        Handler[处理器<br/>HTTP Handlers]
        Middleware[中间件<br/>Auth/CORS/Rate Limit]
    end
    
    subgraph "调度层 - Scheduling Layer"
        Scheduler[调度器<br/>Model Scheduler]
        RunnerRef[运行器引用<br/>Runner References]
        LoadBalancer[负载均衡<br/>Request Queue]
    end
    
    subgraph "推理层 - Inference Layer"
        LLMServer[LLM服务器<br/>Process Manager]
        LlamaRunner[Llama运行器<br/>llama.cpp wrapper]
        OllamaRunner[Ollama运行器<br/>native runner]
    end
    
    subgraph "硬件层 - Hardware Layer"
        GGML[GGML后端<br/>Hardware Abstraction]
        CUDA[CUDA<br/>NVIDIA]
        ROCm[ROCm<br/>AMD]
        Metal[Metal<br/>Apple]
        CPU[CPU<br/>Multi-thread]
    end
    
    CLI --> Router
    WebAPI --> Router
    OpenAI --> Router
    
    Router --> Handler
    Handler --> Scheduler
    
    Scheduler --> RunnerRef
    RunnerRef --> LLMServer
    
    LLMServer --> LlamaRunner
    LLMServer --> OllamaRunner
    
    LlamaRunner --> GGML
    OllamaRunner --> GGML
    
    GGML --> CUDA
    GGML --> ROCm  
    GGML --> Metal
    GGML --> CPU
```

## 🚀 请求处理流程

### HTTP请求到推理输出的完整链路
```mermaid
sequenceDiagram
    participant Client as 客户端
    participant Server as HTTP服务器
    participant Scheduler as 调度器
    participant Runner as 运行器
    participant LLM as 推理引擎
    participant GPU as GPU设备
    
    Client->>Server: POST /api/generate
    Note over Server: 解析JSON请求体
    Server->>Server: 验证模型名称和参数
    
    Server->>Scheduler: GetRunner(model, options)
    Note over Scheduler: 检查模型是否已加载
    
    alt 模型未加载
        Scheduler->>Scheduler: 选择最优GPU组合
        Scheduler->>LLM: NewLlamaServer(gpus, model)
        LLM->>GPU: 分配VRAM并加载模型
        GPU-->>LLM: 模型加载完成
        Scheduler->>Runner: 创建RunnerRef
        Note over Runner: 引用计数设为1
    else 模型已加载
        Scheduler->>Runner: 增加引用计数
    end
    
    Scheduler-->>Server: 返回Runner引用
    
    Server->>Runner: Completion(prompt, images, options)
    Runner->>LLM: 转发推理请求
    
    loop 流式生成
        LLM->>GPU: 执行forward pass
        GPU-->>LLM: 返回logits
        LLM->>LLM: 采样下一个token
        LLM-->>Runner: CompletionResponse{content, done=false}
        Runner-->>Server: 转发响应
        Server-->>Client: HTTP chunk响应
    end
    
    LLM-->>Runner: CompletionResponse{done=true, metrics}
    Runner-->>Server: 最终响应
    Server-->>Client: 结束HTTP stream
    
    Server->>Runner: 释放引用
    Runner->>Runner: 引用计数减1
    
    opt 引用计数为0且超时
        Scheduler->>Runner: 触发模型卸载
        Runner->>LLM: Close()
        LLM->>GPU: 释放VRAM
    end
```

## 🧠 内存管理策略

### 分层内存架构
```mermaid
graph TD
    subgraph "系统内存分配"
        SystemRAM[系统RAM<br/>模型权重+KV缓存]
        VRAM[显存VRAM<br/>GPU计算缓冲区]
        PageCache[页面缓存<br/>模型文件缓存]
    end
    
    subgraph "内存优化技术"
        Quantization[模型量化<br/>FP16/INT8/INT4]
        KVCache[KV缓存<br/>注意力缓存复用]

        Offloading[内存卸载<br/>CPU-GPU动态交换]
    end
    
    subgraph "调度策略"
        LRU[LRU淘汰<br/>最近最少使用]

    end
    
    SystemRAM --> Quantization
    VRAM --> KVCache
    PageCache --> MemoryPool
    
    Quantization --> LRU
    KVCache --> RefCount
    MemoryPool --> Preload
    Offloading --> RefCount
```

### 模型加载生命周期
```mermaid
stateDiagram-v2
    [*] --> NotLoaded: 初始状态
    NotLoaded --> Loading: 收到推理请求
    Loading --> Loaded: 加载成功
    Loading --> Failed: 加载失败
    Failed --> [*]: 清理资源
    
    Loaded --> Serving: 开始推理
    Serving --> Loaded: 推理完成
    Loaded --> Unloading: 空闲超时
    Unloading --> [*]: 释放内存
    
    note right of Loading
        检查GPU内存
        分配VRAM空间
        加载模型权重
        初始化KV缓存
    end note
    
    note right of Serving
        处理并发请求
        维护引用计数
        监控资源使用
    end note
```

## 📊 性能监控指标

### 关键性能指标
| 指标类别 | 指标名称 | 说明 | 正常范围 |
|----------|----------|------|----------|
| **延迟** | 首token延迟 | 第一个token生成时间 | < 500ms |
| **延迟** | token间延迟 | 相邻token生成间隔 | < 50ms |
| **吞吐** | tokens/秒 | 每秒生成token数量 | 20-100 |
| **资源** | GPU利用率 | GPU计算资源使用 | 60-90% |
| **资源** | 内存使用率 | VRAM占用百分比 | < 80% |
| **并发** | 活跃请求数 | 同时处理的请求 | < CPU核数×2 |
