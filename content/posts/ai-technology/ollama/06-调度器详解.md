# 调度器详解

## 🎯 调度器职责

调度器(Scheduler)是Ollama的**资源管理中枢**，负责模型的智能调度、生命周期管理和资源优化分配。

    end
    
    subgraph "通信通道"

## 🔄 调度流程详解

### 请求调度状态机
```mermaid

    Pending --> CheckLoaded: 检查模型状态
    CheckLoaded --> Serving: 模型已加载
    CheckLoaded --> Queueing: 模型未加载
    
    Queueing --> Loading: 开始加载模型
    Loading --> LoadSuccess: 加载成功
    Loading --> LoadFailed: 加载失败
    
    LoadSuccess --> Serving: 开始服务
    LoadFailed --> [*]: 返回错误
    
    Serving --> Completed: 请求完成
    Completed --> [*]: 释放资源
    
    note right of CheckLoaded
        检查loaded map
        验证运行器状态
        增加引用计数
    end note
    
    note right of Loading
        选择最优GPU组合
        分配VRAM空间  
        启动推理进程
        等待就绪信号
    end note
```

### GPU资源选择算法
```mermaid
flowchart TD
    Start[开始选择GPU] --> GetGPUs[获取可用GPU列表]
    GetGPUs --> CheckMemory{检查内存需求}
    
    CheckMemory -->|单GPU足够| SingleGPU[选择最优单GPU]
    CheckMemory -->|需要多GPU| MultiGPU[多GPU组合选择]
    CheckMemory -->|内存不足| Evict[触发模型淘汰]
    
    SingleGPU --> RankGPU[GPU性能排序<br/>1.可用内存<br/>2.计算能力<br/>3.当前负载]
    MultiGPU --> CombineGPU[GPU组合优化<br/>1.内存总和<br/>2.通信开销<br/>3.负载均衡]
    
    Evict --> SelectEvict[选择淘汰对象<br/>1.LRU算法<br/>2.引用计数为0<br/>3.内存占用大小]
    SelectEvict --> UnloadModel[卸载选中模型]
    UnloadModel --> CheckMemory
    
    RankGPU --> AllocateGPU[分配GPU资源]
    CombineGPU --> AllocateGPU
    
    AllocateGPU --> Success[分配成功]
    
    Success --> End[结束选择]
```

## 📊 运行器引用管理

### RunnerRef生命周期
```mermaid
sequenceDiagram
    participant S as Scheduler
    participant R as RunnerRef  
    participant L as LlamaServer
    participant G as GPU
    
    Note over S: 收到模型请求
    S->>R: 创建RunnerRef
    R->>R: 初始化引用计数=1
    
    R->>L: 创建LlamaServer
    L->>G: 分配GPU内存
    G-->>L: 内存分配完成
    L-->>R: 服务器就绪
    
    R->>S: 注册到loaded map
    S-->>S: 返回RunnerRef给请求者
    
    loop 服务请求
        Note over R: 新请求到达
        R->>R: 增加引用计数
        R->>L: 转发推理请求
        L->>G: 执行推理计算
        G-->>L: 返回推理结果
        L-->>R: 推理完成
        R->>R: 减少引用计数
    end
    
    Note over R: 空闲超时检查
    alt 引用计数=0 且 超过keepAlive时间
        S->>R: 触发卸载
        R->>L: 停止服务器
        L->>G: 释放GPU内存
        G-->>L: 内存释放完成
        L-->>R: 服务器关闭
        R->>S: 从loaded map移除
        R->>R: 销毁RunnerRef
    end
```

### 引用计数实现
```go
type runnerRef struct {
    refCount      atomic.Int32
    sessionDuration *api.Duration
    lastUsed      time.Time
    // ... 其他字段
}

// 获取运行器引用（增加计数）
func (r *runnerRef) acquire() {
    r.refCount.Add(1)
    r.lastUsed = time.Now()
}

// 释放运行器引用（减少计数）  
func (r *runnerRef) release() {
    count := r.refCount.Add(-1)
    if count == 0 {
        // 启动超时检查
        r.scheduleTimeout()
    }
}

// 检查是否可以卸载
func (r *runnerRef) canUnload() bool {
    if r.refCount.Load() > 0 {
        return false // 仍有活跃请求
    }
    
    timeout := r.sessionDuration.Duration
    return time.Since(r.lastUsed) > timeout
}
```

## 🧹 垃圾回收机制

### 自动清理流程
```mermaid
flowchart TD
    Timer[定时器触发<br/>每30秒检查] --> ScanRunners[扫描所有运行器]
    
    ScanRunners --> CheckRef{检查引用计数}
    CheckRef -->|refCount > 0| Skip[跳过活跃运行器]
    CheckRef -->|refCount = 0| CheckTimeout{检查超时}
    
    CheckTimeout -->|未超时| Skip
    CheckTimeout -->|已超时| MarkUnload[标记为待卸载]
    
    MarkUnload --> SendExpire[发送到expiredCh]
    SendExpire --> UnloadWorker[卸载工作器处理]
    
    UnloadWorker --> StopServer[停止LlamaServer]
    StopServer --> ReleaseGPU[释放GPU内存]
    ReleaseGPU --> RemoveRef[从loaded map移除]
    
    RemoveRef --> LogCleanup[记录清理日志]
    LogCleanup --> Complete[清理完成]
    
    Skip --> Timer
    Complete --> Timer
```

### 关键性能指标监控
| 指标 | 描述 | 目标值 | 监控方法 |
|------|------|--------|----------|
| **模型加载时间** | 从请求到模型就绪 | < 10s | 时间戳diff |
| **调度延迟** | 请求排队到开始处理 | < 100ms | 队列时间统计 |
| **内存利用率** | GPU内存使用效率 | 70-90% | CUDA/ROCm API |
| **并发处理数** | 同时处理的请求数量 | 符合硬件能力 | 引用计数统计 |
| **模型命中率** | 请求模型已加载比例 | > 80% | 缓存命中统计 |
