# 扩展

## 摘要

扩展是使用新数据、要求、方法和状态机扩展Agent2Agent（A2A）协议的手段。代理在其[`AgentCard`](/specification/#5-agent-discovery-the-agent-card)中声明对扩展的支持，然后客户端可以选择扩展提供的行为作为他们向代理发出请求的一部分。扩展由URI标识并由其扩展规范定义。任何人都能够定义、发布和实现扩展。

## 介绍

核心A2A协议是启用代理之间通信的坚实基础。然而，很明显，某些领域需要比协议中通用方法提供的更多结构。扩展被添加到协议中以帮助支持这些情况：通过扩展，代理和客户端可以协商额外的、自定义逻辑，以在核心协议之上分层。

### 扩展的范围

可能使用扩展的确切方式集合是故意未定义的。这是为了促进使用扩展将A2A扩展到目前已知用例之外的能力。然而，一些用例是明显可预见的，例如：

- 在`AgentCard`中暴露新信息。扩展可能根本不影响请求/响应流程——它可以仅仅用作通过`AgentCard`向客户端传达额外结构化信息的方式。我们将这些称为*仅数据扩展*。例如，扩展可以向其`AgentCard`添加关于代理GDPR合规性的结构化数据。

- 在核心请求/响应消息上覆盖额外的结构和状态变更要求。例如，扩展可以要求所有消息使用遵循特定模式的`DataPart`。这种类型的扩展有效地充当核心A2A协议的配置文件，缩小允许值的空间。我们将这些称为*配置文件扩展*。例如，医疗保健扩展可以强制要求包含患者信息的所有`Message`部分必须加密并放置在符合FHIR标准的`DataPart`中。

- 完全添加新的RPC方法。扩展可以定义代理实现的不仅仅是核心协议方法集。我们将这些称为*方法扩展*。例如，['task-history'扩展](https://github.com/a2aproject/A2A/issues/585#:~:text=Details%20with%20an%20example)可能添加`tasks/search` RPC方法来检索先前任务的列表。

扩展*不*允许对协议进行一些更改。这些是：

- 更改核心数据结构的定义。不支持向协议定义的数据结构添加新字段或删除必需字段。扩展应在核心数据结构上存在的`metadata`映射中放置自定义属性。
- 向枚举类型添加新值。相反，扩展应使用现有枚举值并在`metadata`字段中注释额外的语义含义。

这些限制的存在是为了防止扩展破坏客户端和代理执行的核心类型验证。

## 扩展声明

代理通过在其`AgentCapabilities`对象中包含`AgentExtension`对象在其`AgentCard`中声明对扩展的支持。

| 字段名称       | 类型      | 必需 | 描述                                                                                 |
| :------------ | :-------- | :--- | :----------------------------------------------------------------------------------- |
| `uri`         | `string`  | 是   | 扩展的URI。这是扩展规范定义的任意标识符。扩展的实现使用此URI来标识何时激活，客户端使用此URI来确定扩展兼容性。                                                        |
| `required`    | `boolean` | 否   | 代理是否要求客户端使用此扩展。 |
| `description` | `string`  | 否   | 代理如何使用声明的扩展的描述。扩展的完整详细信息旨在在扩展规范中。此字段用于解释代理和扩展之间的连接。                                    |
| `params`      | `object`  | 否   | 扩展特定的配置。此字段中要放置的预期值（如果有）由扩展规范定义。此字段可用于指定扩展参数或声明额外的代理特定数据。                                          |

显示扩展的示例`AgentCard`：

```json
{
    "name": "Magic 8-ball",
    "description": "一个可以告诉你未来的代理...也许。",
    "version": "0.1.0",
    "url": "https://example.com/agents/eightball",
    "capabilities": {
        "streaming": true,
        "extensions": [
            {
                "uri": "https://example.com/ext/konami-code/v1",
                "description": "提供作弊代码以解锁新财富",
                "required": false,
                "params": {
                    "hints": [
                        "当你的模拟人生需要快速赚钱时",
                        "你可能会否认，但我们已经看到了那些牛的证据。"
                    ]
                }
            }
        ]
    },
    "defaultInputModes": ["text/plain"],
    "defaultOutputModes": ["text/plain"],
    "skills": [
        {
            "id": "fortune",
            "name": "算命师",
            "description": "从神秘的魔法8球寻求建议",
            "tags": ["神秘", "不可信"]
        }
    ]
```

### 必需扩展

虽然扩展是启用额外功能的手段，但我们预期某些代理将具有比核心A2A协议可表达的更严格的要求。例如，代理可能要求所有传入消息都由其作者进行加密签名。声明为`required`的扩展旨在支持此用例。

当`AgentCard`声明必需扩展时，这向客户端发出信号，表明扩展的某些方面影响请求的结构。代理不应将仅数据扩展标记为必需，因为对如何向代理发出请求没有直接影响。

如果`AgentCard`声明了必需扩展，而客户端不请求激活该必需扩展，代理应拒绝传入请求并返回适当的错误代码。

如果客户端请求扩展激活，但不遵循扩展定义的协议，代理应拒绝请求并返回适当的验证失败消息。

## 扩展规范

扩展的详细信息由规范定义。此文档的确切格式未指定，但应至少包含：

- 扩展实现应识别和响应的特定URI。多个URI可以标识同一个扩展，以考虑版本控制或规范文档位置的更改。鼓励扩展作者使用永久标识符服务，如[w3id](https://w3id.org)，以避免URL激增。

- 在`AgentCard`中暴露的`AgentExtension`对象的`params`字段中指定的对象的模式和含义。

- 在客户端和代理之间传达的任何额外数据结构的模式。

- 请求/响应流程、额外端点或实现扩展所需的任何其他逻辑的详细信息。

### 扩展依赖

扩展可能依赖于其他扩展。此依赖可能是必需的，其中扩展的核心功能无法在没有依赖项存在的情况下运行，或者是可选的，其中当存在另一个扩展时启用某些额外功能。扩展规范应记录依赖及其类型。

依赖在扩展规范内声明，而不是在`AgentExtension`对象中。客户端有责任激活扩展*以及*扩展规范中列出的所有必需依赖项。

## 扩展激活

扩展应默认为非活动状态。这提供了"默认为基线"的体验，其中扩展无感知的客户端不会被扩展提供的详细信息和数据所负担。相反，客户端和代理执行协商以确定为请求激活哪些扩展。此协商由客户端在对代理的HTTP请求中包含`X-A2A-Extensions`头发起。此头的值应是客户端打算激活的扩展URI列表。

客户端可以请求激活任何扩展。代理负责识别请求中支持的扩展并执行激活。任何不被代理支持的请求扩展都可以被忽略。

并非所有扩展都是可激活的：仅数据扩展仅存在于通过代理卡片提供额外信息。客户端仍可请求激活这些扩展。由于扩展在激活时不执行任何额外逻辑，这应该不会对请求产生影响。

某些扩展可能对激活有额外的先决条件。例如，某些敏感扩展可能有相应的访问控制列表，规定谁被允许激活扩展。由代理决定请求的扩展中哪些被激活。

如果客户端请求激活具有必需依赖项的扩展，该客户端还必须请求激活并遵守该依赖扩展的要求。如果客户端不为请求的扩展请求所有必需依赖项，服务器可能会以适当的错误使请求失败。

一旦代理识别了所有激活的扩展，响应应包含标识所有激活扩展的`X-A2A-Extensions`头。

显示扩展激活的示例请求：

```HTTP
POST /agents/eightball HTTP/1.1
Host: example.com
Content-Type: application/json
X-A2A-Extensions: https://example.com/ext/konami-code/v1
Content-Length: 519

{
  "jsonrpc": "2.0",
  "method": "message/send",
  "id": "1",
  "params": {
    "message": {
        "kind": "message",
        "messageId": "1",
        "role": "user",
        "parts": [{"kind": "text", "text": "哦，魔法8球，今天会下雨吗？"}]
    },
    "metadata": {
        "https://example.com/ext/konami-code/v1/code": "motherlode",
    }
  }
}
```

以及回显激活扩展的相应响应：

```HTTP
HTTP/1.1 200 OK
Content-Type: application/json
X-A2A-Extensions: https://example.com/ext/konami-code/v1
Content-Length: 338

{
  "jsonrpc": "2.0",
  "id": "1",
  "result": {
    "kind": "message",
    "messageId": "2",
    "role": "agent",
    "parts": [{"kind": "text", "text": "中了！"}],
  }
}

```

## 实现考虑

虽然A2A协议定义了扩展的"什么"，但本节提供关于"如何"的指导——创作、版本控制和分发扩展实现的最佳实践。

### 版本控制

扩展规范将不可避免地发展。拥有清晰的版本控制策略对于确保客户端和代理可以协商兼容的实现至关重要。

- **建议**：使用扩展的URI作为主要版本标识符。我们建议直接在URI路径中包含版本号，例如`https://example.com/ext/my-extension/v1`或`https://example.com/ext/my-extension/v2`。
- **破坏性更改**：当对扩展的逻辑、数据结构或必需参数引入破坏性更改时，**必须**使用新的URI。这防止了歧义并确保支持`/v1`的代理不会错误地处理`/v2`请求。
- **处理不匹配**：如果客户端请求代理不支持的扩展版本（例如，客户端请求`/v2`但代理仅支持`/v1`），代理**应该**忽略该扩展的激活请求。代理**绝不能**尝试"回退"到不同版本，因为客户端的逻辑明确绑定到请求的版本。

### 可发现性和发布

为了使扩展有用，其他开发者需要能够找到其规范并了解如何使用它。

- **规范托管**：扩展规范文档**应该**托管在扩展的URI上。这允许开发者通过简单解析标识符轻松访问文档。
- **永久标识符**：为了防止断开链接或更改域的问题，鼓励作者为其扩展URI使用永久标识符服务，如[w3id.org](https://w3id.org)。
- **社区注册表（未来）**：未来，A2A社区可能建立中央注册表来发现和浏览可用扩展。

### 打包和重用性

为了促进采用，扩展逻辑应打包到可重用库中，可以轻松集成到现有的A2A客户端和服务器应用程序中。

- **分发**：扩展实现应作为其语言生态系统的标准包分发（例如，Python的PyPI包，TypeScript/JavaScript的npm包）。

- **简化集成**：目标应该是开发者的近乎"即插即用"体验。设计良好的扩展包应该允许开发者以最少的代码将其添加到服务器中，例如：

    ```python
    # 假设的Python服务器集成
    from konami_code_extension import CheatCodeHandler
    from a2a.server import A2AServer, DefaultRequestHandler

    # 扩展钩入请求处理器以处理其逻辑
    extension = CheatCodeHandler(description="")
    extension.add_cheat(
        code="motherlode",
        hint="当你的模拟人生需要快速赚钱时",
    )
    extension.add_cheat(
        code="thereisnocowlevel",
        hint="你可能会否认，但我们已经看到了那些牛的证据。",
    )
    request_handler = DefaultRequestHandler(
        agent_executor=MyAgentExecutor(extension),
        task_store=InMemoryTaskStore(),
        extensions=[extension]
    )

    server = A2AServer(agent_card, request_handler)
    server.run()
    ```

### 安全

扩展修改A2A协议的核心行为，因此引入新的安全考虑。

- **输入验证**：扩展引入的任何新数据字段、参数或方法**必须**由实现严格验证。将来自外部方的所有扩展相关数据视为不受信任的输入，除非有协议定义的建立信任的手段。
- **`required`扩展的范围**：在`AgentCard`中将扩展标记为`required: true`时要谨慎。这为所有客户端创建了硬依赖。仅对代理核心功能和安全态势基本的扩展使用此设置（例如，消息签名扩展）。
- **身份验证和授权**：如果扩展添加新方法，实现**必须**确保这些方法受到与核心A2A方法相同的身份验证和授权检查。扩展**绝不能**提供绕过代理主要安全控制的方法。
